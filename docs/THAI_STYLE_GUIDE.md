# แนวทางการแปล Security 51 ภาษาไทย

เอกสารนี้ใช้กับข้อความที่ผู้เล่นเห็นทั้งหมด เป้าหมายคือภาษาไทยที่กระชับ อ่านทันระหว่างเล่น และรักษาบรรยากาศกดดันของเกม โดยไม่เปลี่ยนข้อมูลที่ผู้เล่นต้องใช้ตัดสินใจ

## น้ำเสียง

- UI และคำสั่งระบบใช้ภาษากระชับและเป็นกลาง เช่น `Continue` → `ดำเนินการต่อ`
- เจ้าหน้าที่ใช้ถ้อยคำตรง หนักแน่น และสุภาพตามสถานการณ์ ไม่เติมคำลงท้ายทุกประโยค
- บทสนทนาให้คงบุคลิกและอารมณ์เดิม รวมทั้งความลังเล การพูดซ้ำ และเครื่องหมายวรรคตอนที่มีผลต่อจังหวะ
- เอกสารราชการใช้ภาษาทางการ ส่วนบันทึกส่วนตัวและข่าวใช้ระดับภาษาตามผู้เขียน
- ไม่แปลแบบคำต่อคำเมื่อทำให้ประโยคไทยแข็งหรือยาวเกินกรอบ แต่ห้ามตัดเงื่อนไข ตัวเลข ชื่อ หรือคำใบ้

## ศัพท์และชื่อเฉพาะ

- ใช้คำตาม `translations/glossary/glossary.csv` ก่อนเสมอ
- ชื่อบุคคล โครงการ สถานที่ และรหัสที่ยังไม่มีข้อสรุปให้ทับศัพท์อย่างสม่ำเสมอ ห้ามเดาความหมาย
- `pass` ที่หมายถึงเอกสารผ่านจุดตรวจใช้ `บัตรผ่าน`; กริยาอนุญาตให้ผ่านใช้ `ให้ผ่าน`
- `day` ใน UI รอบการเล่นใช้ `วันที่` เช่น `Day {0}` → `วันที่ {0}`
- ชื่อภาษาแสดงเป็นชื่อที่เจ้าของภาษาใช้; เพิ่มภาษาไทยเป็น `ไทย`

## UI

- ปุ่มใช้คำกริยาสั้นและไม่ใส่จุดท้ายข้อความ
- คำถามยืนยันต้องบอกผลกระทบชัดเจน โดยรักษาการขึ้นบรรทัดของต้นฉบับเมื่อใช้แยกคำเตือน
- ใช้ `ตกลง` สำหรับ `OK/Okay`, `ใช่` สำหรับ `Yes`, และ `ไม่` สำหรับ `No`
- `Back` ใช้ `ย้อนกลับ`; `Quit` ใช้ `ออก`; `Quit Game` ใช้ `ออกจากเกม`
- หลีกเลี่ยงวงเล็บและคำอธิบายเพิ่ม หากข้อมูลนั้นไม่มีในต้นฉบับ

## บทสนทนา

- รักษาจำนวนประโยคและเจตนาของผู้พูด แต่ปรับลำดับคำให้เป็นธรรมชาติในภาษาไทย
- ใช้สรรพนามเท่าที่บริบทระบุได้ หากไม่รู้เพศหรือสถานะให้ละสรรพนามแทนการเดา
- คำสบถและภัยคุกคามแปลตามระดับความรุนแรงเดิม ไม่ทำให้อ่อนหรือแรงขึ้นโดยไม่มีเหตุผล
- เก็บ `...`, `?!`, ตัวพิมพ์ใหญ่ที่สื่อการตะโกน และการเว้นช่วงในรูปแบบที่ภาษาไทยอ่านได้

## ข้อกำหนดทางเทคนิค

- ห้ามแก้ `key`, ลำดับ placeholder หรือชื่อ placeholder เช่น `{0}`
- ต้องรักษา rich-text tag ทุกตัวและการซ้อน tag เช่น `<b>...</b>`
- รักษา line break เมื่อมีความหมายด้านโครงสร้าง; เปลี่ยนได้เฉพาะเมื่อทดสอบในเกมแล้ว
- ไฟล์ข้อความทั้งหมดใช้ UTF-8 และห้ามมี mojibake เช่น `à¸`, `à¹` หรือ `�`
- ห้ามแปลค่า `#N/A`, path, identifier, debug marker และข้อความที่ระบุว่าเป็น translator instruction
- เมื่อข้อความเดียวกันต่างบริบท ให้ยึด key/category และภาพในเกม ไม่บังคับใช้คำแปลเดียวกันโดยไม่ตรวจบริบท

## สถานะคำแปล

- `untranslated`: ยังไม่มีคำแปล
- `draft`: แปลรอบแรกแล้ว
- `reviewed`: ตรวจภาษาและ glossary แล้ว
- `in-game verified`: ตรวจในบริบทจริงแล้วว่าเนื้อหาและ layout ถูกต้อง

ข้อความจะถือว่าเสร็จสมบูรณ์เมื่อเป็น `in-game verified`; การผ่าน validator เพียงอย่างเดียวยังไม่ยืนยันคุณภาพภาษาและการจัดวาง
