# รายงาน Visual QA

วันที่อัปเดต: 3 กันยายน 2026

## หลักฐานที่ยืนยันแล้ว

- Steam build `25104142` เปิดผ่าน BepInEx และปลั๊กอินโดยไม่มี plugin error
- runtime สร้าง TextMeshPro fallback จาก `NotoSansThai-Variable.ttf` ที่รวมในแพ็กเกจ
- I2 Localization โหลดและฉีดคำแปล `3,457/3,457`
- ทดสอบ runtime เดียวกันจากทั้งโฟลเดอร์เกมหลักและสำเนาเกมเต็มแล้ว

## สิ่งที่ยังต้องตรวจจากภาพ

- เมนูหลักและหน้าตั้งค่า: glyph ไทย สระ/วรรณยุกต์ และปุ่มข้อความสั้น
- หน้าด่านตรวจ: เอกสาร บัตร รายการความผิดปกติ และข้อความแจ้งเตือน
- กล่องบทสนทนา: การตัดบรรทัด ชื่อผู้พูด และบรรทัดยาว
- ห้องแยกกักและปฏิบัติการในเมือง: หน้าช่วยเหลือใหม่จาก build `25104142`
- หน้าฉากจบ: บทสนทนา `DM_Ends` และข้อความยาวหลายบุคลิก
- ความละเอียดอย่างน้อย 1920×1080 และความละเอียด/อัตราส่วนที่ผู้ใช้ใช้งานจริง

## สถานะ

`PENDING_INTERACTIVE_CAPTURE`

การทดสอบจาก command session วันที่ 3 กันยายน 2026 ยืนยันว่าเกมสร้างหน้าต่าง 1920×1080 และมี `MainWindowHandle` จริง แต่ยังไม่สามารถเก็บภาพเนื้อหาเกมที่ใช้ตรวจภาษาไทยได้:

- `CopyFromScreen` จับได้เฉพาะหน้าต่าง Codex/Steam ที่อยู่ด้านหน้า เพราะ Windows ไม่อนุญาตให้ command session แย่ง foreground
- `SetForegroundWindow` และ `WScript.Shell.AppActivate` ไม่สามารถนำหน้าต่างเกมขึ้นหน้า (`AppActivate=False`)
- `PrintWindow(PW_RENDERFULLCONTENT)` อ่านหน้าต่าง DirectX/Unity ได้เป็นภาพดำทั้งเฟรม

ไฟล์หลักฐานการทดสอบอยู่ที่ `reports/visual-desktop-mainmenu-25104142.png`, `reports/visual-appactivate-mainmenu-25104142.png` และ `reports/visual-printwindow-mainmenu-25104142.png` ภาพเหล่านี้พิสูจน์ข้อจำกัดของวิธีจับภาพ แต่ไม่ถือเป็นหลักฐานว่าการจัดวางภาษาไทยผ่าน

ขั้นตอนที่ต้องทำในเซสชันผู้ใช้จริงคือเปิดเกมจาก Steam แล้วบันทึกภาพอย่างน้อยเมนูหลัก/ตั้งค่า หน้าด่านตรวจ กล่องบทสนทนายาว และฉากจบ จากนั้นจึงตรวจ glyph สระ/วรรณยุกต์ การตัดบรรทัด และข้อความล้นกรอบได้
